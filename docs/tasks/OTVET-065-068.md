# 065–068 · Маркировка введена: [УРОКИ] и [АСТРО-БЛОГ·пример]

## 065 [УРОКИ] · Кто публикует GitHub Pages
Схема такая: пуш в репо → GitHub Actions сам собирает (vite build)
и сам раскладывает на Pages. Никто не жмёт «опубликовать».
Фраза Кодера «Опубликуйте GitHub Pages» — старая привычка времён,
когда Actions не было и публикация шла руками. В новой схеме она
не нужна: его артефакт — файлы (или коммит через вас), дальше машина.
Если в полигоне Actions ещё нет — это итерация I-1: Кодер сам пишет
workflow-файл, вы один раз пушите, и всё становится само.

## 066 [УРОКИ] · «Писарь в наморднике» — снимаю намордник в полигоне
Ваше замечание верное. Намордник был нужен в ПРОДЕ (astro-blog):
там цена ошибки — боевой сайт. Полигон memorial-korpech-crimea —
ПЕСОЧНИЦА: внутри него Кодеру РАЗРЕШЕНО собирать, запускать dev,
экспериментировать с компонентами и анимациями. Запреты остаются
только три: не открывать чужие репо; не раздувать контекст (3МБ);
не тащить бинарники и «дашборд в дашборде». Это не намордник,
это техника безопасности песочницы.

## 067 [УРОКИ] · Против фризов (уроки mem-OK: 7–9 ответов и конец)
- Сессия Кодера = НЕ БОЛЕЕ 6 ответов; после 5-го он готовит
  handover.md (последний шаг, следующий шаг, последние id) —
  новое окно продолжает с handover, а не с нуля.
- Контекст читается с диска (QWEN.md, ITERATIONS.md, data),
  не пересказывается в чате.
- Данные ОТДЕЛЕНЫ от компонентов (src/data/*.ts): растёт только
  data, компоненты меняются редко — это и есть лечение
  «дашборда в дашборде».
- Один ответ = один артефакт; повторы запрещены (правило О3).

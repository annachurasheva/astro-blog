# 069–072 · Разнос файлов, Actions, логика «Бест Айти»

## 069 [УРОКИ] · Что делает скрипт и как запустить
Скрины дошли: топология ясна — контекст-vkru с дашбордом лежит в
git-projects, головная папка c:\astro-blog (ssh + SC), внутри неё вы
уже создали memorial-korpech-crimea и dashboard-1. Скрипт
scripts/raznos-journal.ps1 (блок 2) делает разнос БЕЗ буфера обмена:
- копирует каркас дашборда (src, index.html, package.json,
  package-lock.json, tsconfig.json) из context-vkru\dashboard
  в astro-blog\memorial-korpech-crimea; node_modules и dist НЕ тащит;
- создаёт то, чего нет: vite.config.js с base './' (чтобы Pages открылся
  по любому пути), .gitignore, workflow deploy-pages.yml,
  docs/revision-1.md (копия разбора), docs/revision-2.md (конспект),
  docs/ITERATIONS.md, QWEN.md, docs/REGULAMENT-MUSEUM.md;
- НИКОГДА не перезаписывает существующее (только «пропуск (уже есть)»);
- пишет журнал действий в c:\astro-blog\reports\raznos-journal.log —
  при проблеме шлёте мне этот лог.
Запуск (один раз, фаза А), из PowerShell:
pwsh -NoProfile -ExecutionPolicy Bypass -File "C:\astro-blog\scripts\raznos-journal.ps1"
dashboard-1 и poligon-* скрипт НЕ трогает; их судьба — потом, руками.

## 070 [УРОКИ] · Подключение «GitHub Actions собирает»
1. В браузере на GitHub: создать ПУСТОЙ публичный репо
   memorial-korpech-crimea (без README и галочек).
2. Запустить скрипт второй раз — фаза Б спросит «репозиторий создан?» —
   ответ «да»: скрипт сделает git init -b main, коммит, remote по SSH
   (git@github.com:annachurasheva/memorial-korpech-crimea.git) и пуш.
   Токены не нужны: только ваш SSH-ключ.
3. На GitHub: Settings → Pages → Source → «GitHub Actions».
4. Адрес пособия: https://annachurasheva.github.io/memorial-korpech-crimea/
   Каждый следующий пуш данных = автосборка и автопубликация;
   никто никогда не жмёт «опубликовать».
Сборка на ubuntu + node 22 (ваш «ремонтный» нод-22 стенд дашборда).

## 071 [УРОКИ·БестАйти] · Логика передачи в музей без стыда
- Музей получает ВИТРИНУ, а не движок: сайт на Pages + пособие +
  регламент на одну страницу; репозиторий и ключи остаются у вас,
  пока juniors не вырастут.
- Регламент (шаблон уже кладётся скриптом): кто главный, куда писать,
  что трогать нельзя, как добавить текст (через вас или джуна),
  где лежат копии. Не-ИТ руководитель читает только его.
- Журнал = аудиторская книга: каждое движение с датой и коммитом.
  Музеи любят документы — это плюс, не минус.
- Без стыда: нейтральные имена (никаких «мучаем»), первоисточники
  и авторство указаны, личных данных нет, лицензия на месте.
- Плита ≥ 3 лет: техника стоит готовая и ждёт; ничего не простаивает —
  пособие уже работает и растёт пакетами по 20–50 записей.

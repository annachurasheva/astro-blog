# 103–105 · Ключ скопировался, но Windows дал ему «слишком открытые» права

## 103 · Диагноз
OpenSSH отклонил СКОПИРОВАННЫЙ ключ: «Permissions ... are too open».
Оригинал в C:\astro-blog\.ssh жил с правильной ACL; копия унаследовала
права папки C:\astro-projects\.ssh (чтение у группы пользователей) —
ssh такие ключи игнорирует. Лечится одной командой icacls.
Заодно: known_hosts вы не скопировали (были две Copy-Item из трёх) —
докопируем.

## 104 · Лечение (по одному движению)
1) Зажать права ключа до «только я»:
icacls C:\astro-projects\.ssh\astro_blog /inheritance:r /grant:r "$($env:USERNAME):(F)"
(если icacls на кастрированной W10 не пустит — запас: вернуть в глобальном
sshCommand старый путь C:/astro-blog/.ssh/astro_blog, у него ACL была верная)
2) Докопировать known_hosts:
Copy-Item C:\astro-blog\.ssh\known_hosts C:\astro-projects\.ssh\ -Force
3) Контроль в revision:
git fetch origin   → жду без «bad permissions» и без Permission denied.

## 105 · Дальше по плану 101–102
- Клон astro-blog (если папка пустая — удалить и клонировать заново):
git clone git@github.com:annachurasheva/astro-blog.git C:\astro-projects\astro-blog
- Ветки разработки во всех трёх репо (main = приёмка, dev = работа):
astro-blog: git switch main-qwen3-coder-plus
memorial: git push -u origin main (если не пушили); git switch -c main-qwen3-coder-plus; git push -u origin main-qwen3-coder-plus
revision: git switch -c main-qwen3-coder-plus; git push -u origin main-qwen3-coder-plus
- Контроль: git branch -vv в каждом репо — вывод мне.
origin2 (https) после восстановления SSH можно снять: git remote remove origin2.

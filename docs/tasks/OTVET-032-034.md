# 032–034 · Лок не трогать, ноду не пересобирать, одна строка в конфиге

## 032 · pnpm-lock.yaml и нода
- pnpm-lock.yaml НЕ убивать никогда: это источник истины. Мы меняли в
  package.json только name и repository — это метаданные, зависимости
  не тронуты, лок остаётся валидным как есть.
- Ноду и node_modules пересобирать НЕ нужно: состав пакетов не менялся.
  У вас на стенде нода и так 24.5.0, `pnpm dev` запустился — значит
  установка живая.

## 033 · Причина ошибки — моя ошибка в 025
Я собрал moreLocales БЕЗ 'zh', а ваше решение было «языки НЕ удалять,
русский первым». Из-за этого схема контента перестала принимать
`lang: zh`, и шаблонная страница src/content/about/about-zh.md валит
проверку. Лечится одной строкой, файлы контента не трогаем:
Старая: `    moreLocales: ['en', 'es', 'ja', 'zh-tw'],`
Новая: `    moreLocales: ['en', 'es', 'ja', 'zh', 'zh-tw'],`
Строка «No files found … posts» — не ошибка, а предупреждение о пустой
папке постов: так и задумано до фазы ваших текстов.

## 034 · Порядок до переезда
1. Внести строку moreLocales (добавить 'zh').
2. git add src/config.ts
   git commit -m "donor: keep zh in moreLocales"
   git push
3. Контроль: pnpm dev — ошибка InvalidContentEntryDataError исчезла
   (останется только предупреждение про пустые посты).
4. Затем команды переезда из 031 (бак + force-with-lease) → деплой →
   пять проверок приёмки → ТОЧКА СТОП.
Пришлите вывод pnpm dev после правки и хэш пуша — закрою цикл.

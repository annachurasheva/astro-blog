# 048–052 · Домены, зачистка полигона, очередь

## 048 · Как устроены домены EdgeOne (ваше непонимание)
У проекта EdgeOne Pages три вида адресов:
1) стабильный домен проекта: `<имя-проекта>.edgeone.dev`
   (astro-blog.edgeone.dev — это он и есть; он не «временный»);
2) превью каждого деплоя: `<проект>-<хэш>.edgeone.dev`
   (mem-2026-dp9rp86flxh6 — это оно; остаётся в истории деплоев);
3) свои домены — подключаются в разделе Domains.
Никто ничего «сам» не меняет: постоянный домен появляется от ИМЕНИ
проекта. Хотите memorial-korpech-crimea.edgeone.dev — создаёте проект
с таким именем (или переименовываете mem-2026) и цепляете свой репо.
Для вилок: один проект = один репо = один стабильный домен;
в клоне меняется одна строка site.url.

## 051 · Зачистка полигона по ревизии EdgeOne AI (без погружения)
Ревизия подтвердила: Umami/Apiflash/imageHost/верификации/комменты —
вылечены. Берём в работу только мелкое и безопасное:

К1 (ход 1): снять .ssh с отслеживания (там pubkey и known_hosts):
git rm -r --cached .ssh
git commit -m "chore: untrack .ssh"
git push
(с диска файлы можно не удалять; из репо они исчезнут)

К2 (ход 2): футер ждёт ГОЛЫЙ email (компонент сам добавит mailto:,
а с нашим 'mailto:…' открывает пустую вкладку):
старая строка: `        url: 'mailto:79787883649@ya.ru',`
новая строка:  `        url: '79787883649@ya.ru',`
commit "fix: bare email for footer mailto", push.

К3 (ход 3): токены по клонам. На КАЖДОМ клоне (C:\astro-blog и полигон SC):
git remote -v
Если в URL мелькает ghu_ — заменить:
git remote set-url origin git@github.com:annachurasheva/astro-blog.git
И один раз на GitHub: Settings → Developer settings → PAT — список пуст
(вы отозвали; сверяем глазами).

К4 (ваше решение): ревизия считает пять пустых языков регрессией
(переключатель ведёт на пустые страницы). Модули i18n НЕ удаляем в любом
случае; вопрос только к ДАННЫМ: moreLocales: [] до появления переводов
(рекомендую) или оставить как есть (пустые страницы видны). Скажите —
внесу одной строкой.

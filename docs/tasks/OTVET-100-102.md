# 100–102 · Разбор ошибок + глобальный SSH + ветки разработки

## 100 · Что случилось (коротко, без вины)
- Ошибка А: sshCommand вы ставили ЛОКАЛЬНО в каждом репо. Свежий clone
  локальных конфигов не имеет → полез дефолтный ssh без ключа →
  Permission denied. Лечится одним ГЛОБАЛЬным sshCommand.
- Ошибка Б: вложенные кавычки в значении config съедаются PowerShell.
  В путях НЕТ пробелов — внутренние кавычки вообще не нужны;
  пишем слеши C:/...
- Ошибка В: «fatal: not in a git directory» — папка astro-blog после
  неудачного клона пустая и не репо; config туда не пишется. После
  глобального sshCommand это и не нужно.
- Ошибка Г: хвостовой «>» в cd — опечатка при копировании; без него всё пошло.

## 101 · Исправление (по одному движению)
1) Ключи в нейтральное место (копия, не перенос):
New-Item -ItemType Directory -Force -Path C:\astro-projects\.ssh
Copy-Item C:\astro-blog\.ssh\astro_blog C:\astro-projects\.ssh\
Copy-Item C:\astro-blog\.ssh\astro_blog.pub C:\astro-projects\.ssh\
Copy-Item C:\astro-blog\.ssh\known_hosts C:\astro-projects\.ssh\
2) Глобальный sshCommand (один раз, на все репо и клоны):
git config --global core.sshCommand "C:/Tools/Scripts/ssh.bat -i C:/astro-projects/.ssh/astro_blog -o UserKnownHostsFile=C:/astro-projects/.ssh/known_hosts"
3) Снять локальные перебивки (в revision и memorial):
git config --unset core.sshCommand
4) Контроль: git ls-remote git@github.com:annachurasheva/astro-blog.git
   (жду список refs, без Permission denied)
5) Пустая папка после неудачного клона: проверьте dir C:\astro-projects\astro-blog;
   если пустая — Remove-Item C:\astro-projects\astro-blog -Force;
   затем: git clone git@github.com:annachurasheva/astro-blog.git C:\astro-projects\astro-blog

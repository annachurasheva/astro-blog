# 024–026 · Диагноз config.ts и чистая замена

## 024 · Что с ним не так
В файле случайные пробелы ВНУТРИ служебных слов — это и есть «неясные
причины»: такие правки ломают синтаксис, сборка падает. Список:

Ошибки синтаксиса (файл не жилец):
1) `ur l:` → `url:`
2) `prima ry:` → `primary:`
3) `/ / used for navbar, selected text, etc` → `// used for navbar, selected text, etc`
4) `se arch: false` → `search: false`
5) последняя строка `replace(//$/, '')` → `replace(/\/$/, '')`
   (у вас `//` превратил регулярное выражение в комментарий — строка обрывается)

Ошибки содержания (не валят сборку, но работают криво):
6) `'es '` → `'es'` (пробел в коде языка — язык не найдётся)
7) `name: 'Ema il'` → `name: 'Email'` (дырка в надписи футера)
8) `'https:/ /unpkg.com/@waline/emojis@1.2.0/tw-emoji'` →
   `'https://unpkg.com/@waline/emojis@1.2.0/tw-emoji'`

Хорошее (сохраняю): i18nTitle false; locale 'ru'; moreLocales без 'ru';
comment enabled false; seo-блок целый; почты и mailto ваши; preload {}.
Subtitle теперь «Памяти павших в ВОВ» — принимаю как ваше решение по
смыслу (вместо прежнего варианта), фиксирую в журнале.

Вывод: латать построчно опасно — пробелы могли сесть и в невидимых мне
местах. Заменяем ВЕСЬ файл чистой версией (блок 025).

## 025 · Чистый config.ts — отдельный блок ниже
Замените ВЕСЬ файл содержимым блока. После замены:
git add src/config.ts
git commit -m "donor: clean config.ts 025"
git push

## 026 · Про провалы пушей и остатки
- Пуш не зависит от содержимого файла: git не читает синтаксис.
  Провалы пуша = сеть/SSH. Лечение: повторить тот же push.
- Если push отклонён (remote впереди): git pull --rebase origin
  main-qwen3-coder-plus-v01, затем push.
- Контроль «всё уехало»: git log origin/main-qwen3-coder-plus-v01..HEAD
  --oneline — пусто значит уехало.
- После пуша 025 остаются две правки из списка 022: пункт 8 (Head.astro,
  pageImage = new URL…) и пункт 9 (package.json, repository — ваш).
  Затем команды 023 (бак + перезапись main) → живой деплой → приёмка → СТОП.

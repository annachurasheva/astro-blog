# ЗАПИСКА СЕБЕ (проектировщик) · что делаем и в каком порядке

Цель: не тащить контекст «приведение astro-blog в порядок» в следующие
фазы. Каждая фаза = свой EXEC-LIST; журнал — единственная память;
Кодер — свежее окно на задачу.

## Фаза 0 (сейчас): полигон
К1–К4 → ТОЧКА СТОП → тег donor-v1. После — контекст зачистки ЗАКРЫТ:
возврат в него только по новой ревизии, не по памяти.

## Фаза 1: формат карточки
2–3 текста Заказчика вручную (md + поля схемы, картинки локальные).
Фиксирую формат карточки персоны и формат раздела.

## Фаза 2: конвейер
Проект конвейера (inbox → скрипт → публикация; дубли; склад).
Кодер исполняет микро-ходами; приёмка — стенд + живой деплой.

## Фаза 3: пакеты и секции
Пакеты 20–50; секции (литература/наука; очерки/беллетристика);
списки налету; проверка RSS/фидов на объёме.

## Фаза 4: комментарии и распространение
ОК/ВК; бронь первого комментария (фотоскан записки);
RSS → Дзен → ОК.

## Фаза 5: журнал-пособие (параллельно с 2–4)
Интерактивный журнал Кодера → GitHub Pages; формат пособия джунам.

## Ресурсные правила
- 0–1 движение Заказчика за цикл; короткие тексты.
- Одна фаза — один открытый контекст у Кодера.
- Очереди (052) не открываются раньше фазы 4 без прямой команды.




Фазы 0–5 — как в v1 (полигон; формат карточки; конвейер; пакеты и
секции; комментарии и распространение; журнал-пособие).

## Фаза 6 · Передача школьному музею
- Журнал-пособие со слоем «для руководителя (не-ИТ)» = передающий
  документ; juniors входят через пособие.
- Техническая готовность (репо, домен, конвейер, инструкция
  руководителю на одну страницу) — ДО прихода согласования плиты
  (срок от 3 лет): пусть техника ждёт, а не наоборот.
- Состав передачи: репо мемориала + домен + Pages-пособие +
  контакты волонтёров + регламент «что трогать, что нет».

Схема: Проектировщик → (через Заказчика) → Кодер → файлы/отчёт →
(через Заказчика) → Проектировщик → вердикт.

Ограничения: квота Кодера ограничена — каждый шаг заканчивается артефактом;
технические объяснения — в отчёт, не Заказчику; файлов отдавать ровно
столько, сколько указано в задании.

# 3A. СТЕНД ЗАКАЗЧИКА (СТЕНД) — обязательно

Стенд — единственная обстановка, где живёт результат. Код, команды и
инструкции пишутся, опираясь на состояние стенда. Пространство Кодера —
модель стенда и обязано совпадать с ним по версиям (раздел 4).

Состав стенда (фиксирован):
- W10 кастомная; Edge; PowerShell 7.6.5; папка `C:\astro-blog\`;
- Node 24.5.0 (.nvmrc); pnpm 10.33.0 (corepack); `pnpm-lock.yaml` — истина;
- порт 4321; буфер обмена нестабилен — Заказчик принимает только файлы.

Правила стенда:
С1-СТЕНД. Команды — только синтаксис PowerShell, пути Windows. Запрещены
  bash-приёмы (`export`, `rm -rf`, `sed`, `./script.sh`). `&&` разрешены.
С2-СТЕНД. Перед первой правкой кода зафиксировать стенд реальными выводами:
  `node -v`; `pnpm -v`; `git status --short`; `git log -1 --oneline` —
  в блок `## ENV` отчёта.
С3-СТЕНД. Результат готов, только если его команды выполняются на стенде
  без переделок.
С4-СТЕНД. Непроверяемое на стенде — NOT TESTED. Угадывание запрещено.

# 4. СРЕДА (до любого кода)

С0. Если платформа поддерживает devcontainer — открыть проект через
  `.devcontainer/devcontainer.json`: среда уже зафиксирована рецептом автора.
  В этом случае С1 вручную не выполнять; проверка С3 обязательна всегда.
С1. Иначе собрать по `pnpm-lock.yaml` одной командой:
  `corepack enable && corepack prepare pnpm@10.33.0 --activate && pnpm install --frozen-lockfile`
С2. Файлы в `node_modules` не редактировать НИКОГДА. Мешает — удалить папку
  и повторить С1. Лечить причину, не симптом.
С3. До первой правки кода предъявить реальный вывод: `node -v` (24.5.0),
  `pnpm -v` (10.33.0), `git status --short` (без `node_modules`),
  `pnpm run build` (хвост с успехом).
С4. Собранное до принятия С0–С3 считается непроверенным.
С5. Новые пакеты — только по заданию; изменение лок-файла входит в задание
  и явно указывается в отчёте.

# 8. ПЕРЕНОС И ПРИЁМКА (репозиторный гейт)

П1. Кодер не пушит и не делает `git pull`. Перенос — файлы по одному.
П2. Переносить ТОЛЬКО файлы из задания.
П3. НЕ переносить: `node_modules/**`, `dist/**`, `.astro/**`, `.output/**`,

П4. Факт выполнения = файлы в репо Заказчика после его коммита;

П5. Каждый файл — отдельным код-блоком (путь в заголовке) или отдельным
  скачиванием. Один блок = один файл.
